# Harness engineering principles and harness standards

**Verdict: PARTIAL, 3/5.** The engine has real machinery (durable journal, typed reports, watchdog exit codes, role gate, worktrees, 1183 passing tests), but cost caps, tracing, evals and secret scanning stop short of the standard the intent sets.

Audited at `41a5327` (`main`). Paths are relative to the repo root. `src/` means `crates/quaqua/src/`. `tpl/` means `templates/workspace/`.

## Scope

**Harness engineering**
- "The harness, not the model, owns reliability; models and agent kinds swap through config with no workflow change."
- "Rules become machinery: anything repeated turns into a hook, a gate, a lint, or an exit code, and prose is the fallback."
- "Evidence over trust: work counts only when its report and rerun tests prove it; no agent grades its own work."
- "Full observability: every run, verdict, failure, and cost is recorded and auditable."
- "Engineered properly: a daemon, bus, database, or service is used whenever it is the right design."

**Harness standards**
- Context engineering, tool and permission design, isolation, state and checkpoints, structured handoffs, evals, tracing, guardrails, failure taxonomy, versioned harness, provider neutrality (quoted per row below).

## Fixes

Ranked by impact on the success signal (goal to merged, verified change with approvals as the only owner touch).

1. Make cost a hard cap. Reject `on_cost_cap = "kill"` on a harness with no stop sequence at config load, add a pane-kill fallback for those harnesses, and default to `kill` once spend is readable. Add an agy spend reader or a time-priced proxy.
2. Have the engine rerun the brief's verify command at the report SHA and record a `verifier` verdict, so acceptance does not depend on the CoS remembering to rerun.
3. Unify tracing: one run id on journal events, telemetry rows and verdicts, plus a `merge` event with the incoming SHA. Wire or delete `JsonlSpanSink`.
4. Record one end-to-end run as an eval fixture and gate harness changes on it. Add the shell suites, Node tests, clippy and fmt to CI.
5. Scan worker diffs and reports for secrets with the existing `scan_secrets` before a report is accepted.
6. Check a builder's diff against the brief's owned and forbidden paths at acceptance.
7. Move harness facts (launch args, stop keys, spend reader) behind a config-described adapter so a new harness is data, not a Rust edit.
