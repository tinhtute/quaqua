# retro327-11: Peer `grep` with `${QQ` raises a permission prompt

Date: 2026-11-23 · Base: main ad67749 · Branch: quaqua/sude-r11 · Issue: tinhtute/quaqua#327 finding 11

## Verdict

The prompt comes from the Claude Code harness (2.1.330), outside this repo. No repo change fixes it. The repo's own gate allows the command.

## Evidence

1. Repo gate: `quaqua gate` returns exit 0 for `grep -n "${QQ" f.txt` and `rg -n "${QQ" f.txt`. `herdr-gate.sh` only execs `quaqua gate` or falls back to the guarded list (push, merge, herdr pane, qq.db, ...); no rule matches.
2. Peer profile: `spawn.rs` writes no permission profile (no allow rules, no `--allowedTools`). The only permission settings are `templates/workspace/.claude/settings.json` (`deny: ["Agent"]` plus hooks).
3. Harness repro (scratch dir, `claude -p --model haiku --settings allow.json`, allow = `Bash(grep:*)`, `Bash(rg:*)`; no quaqua state touched):

| command | result |
|---|---|
| `grep -n "QQ" f.txt` | runs |
| `grep -n "${QQ" f.txt` | permission denied (prompt in interactive) |
| `rg -n "${QQ" f.txt` | permission denied |
| `grep -n '${QQ' f.txt` (single quotes) | runs |

An allow rule does not clear it: the harness safety check treats `${...}` inside double quotes as a parameter expansion it cannot prove read-only. That is the same check that makes an interactive Peer (it runs in a herdr pane) stop on a prompt.

## Workaround (docs/brief level, no code)

Search literal text with fixed-string search and single quotes: `grep -nF '${QQ' f` or `rg -nF '${QQ' f`. Both run and match.

Do not rely on the single-quoted regex form (`grep -n '${QQ' f`): it runs but finds nothing in a Claude Code Bash session, where `grep` is a shell function running `ugrep -G`; `rg -n '${QQ' f` errors with `repetition quantifier expects a valid decimal`. `${` is a regex quantifier start, so only `-F` is safe.

The worker-facing rule (`crates/qq-core/templates/workspace/.claude/rules/brief.md`) now carries the `-F` line; finding 11 is closed by it.

## Not done

No allow rule added: it would not help (see table row 2) and would widen Peer permissions for nothing.
