# Inner / outer harness: sources (fetched 2026-11-13, TinyFish fetch_content)

- Holmes, X post 2026-10-06 (https://x.com/BHolmesDev/status/2107588784275816461): "inner loop is your team of agents building everything, and the outer loop is your team of supervisors / gardeners watching over those agents and spotting room for improvement". His outer loop today: agents score worker conversations (efficiency, wasted tool calls, code to standard); a scheduled agent reads low scores and proposes skill changes; scores gauge whether merged skill changes help. Next: outer agents for architecture and static-analysis checks.
- Fowler/Böckeler, "Harness engineering for coding agent users" 2026-04-02 (https://martinfowler.com/articles/harness-engineering.html): Agent = Model + Harness. Built-in harness of the agent vs the user's "outer harness". Guides (feedforward) and sensors (feedback), each computational or inferential. Steering loop: a recurring issue upgrades a guide or sensor. Keep quality left; drift sensors run outside the change lifecycle.
- Thoughtworks, Pani & Nandyala 2026-09-29 (https://www.thoughtworks.com/insights/blog/architecture/engineering-the-harness-a-practical-pattern-for-reliable-coding-agents): guides, sensors, selective human gates; least-privilege tools; silent success / verbose failure; promote prose rules to mechanical checks; treat the harness as versioned software. Does not use the words inner/outer.
- anh iu 2026-11-13: inner today = the pstack playbooks or monoharness (~/Lab/mono-harness, eb6c883: skills + zharness doc protocol, "not an agent orchestrator").
