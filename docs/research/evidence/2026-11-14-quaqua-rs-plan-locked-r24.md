# Harness, Loop and Graph: the enhanced edition of agent engineering with a Chief of Staff

## Goal
- outcome: quaqua is rewritten as a new crate beside the old one in ~/Lab/quaqua and swapped in with one main merge, so that it works as a basic software factory run by a Chief of Staff. A long-running farm daemon is the hub: the CoS or a Lead on herdr fans out workers across any harness (claude, pi, agy, opencode, codex later, others) chosen per kind; the daemon owns dispatch, liveness, one home for state, event-driven journaling, the fence, the task DAG, schedules and triggers, and the CLI is its client. Roles are anh iu, the CoS (chief: intake, project-level integration), the Supervisor (governance: observes, scores, asks Leads, proposes; no orders, no acceptance), at most one Lead per project (sole arbiter inside its project) and Peers (one bounded outcome each, spawned by that Lead or, for a project without a Lead, by the CoS; implementation tools only, no orchestration, no peer mail). Harness, model, effort, roster and role topology are data in a SQLite config: `quaqua init` seeds it from toml, edits go through `quaqua config set` / `rename-kind`, `quaqua config export` dumps toml, engine default changes surface via `config diff`. Per-project tactics live in a `WORKSPACE_PROTOCOL.md` in each repo, read by the daemon and the Lead. A new harness runs through a generic driver with no rebuild. Graph = task DAG + role topology graph (spawn/mail/report edges) + code knowledge graph. KB = zbrain plus the code KG, read-only for workers, over a fixed entity schema in SQLite. Every run is recorded (events, transcript, tool calls, tokens/cost, artifacts, candidate sha) and read through the CLI. Inner loop = workers running the skill set of their role, injected per driver. Outer loop = three proactive loops feeding one risk-split backlog: bug fixes from failure signals, self-improvement from scored conversations, product work from feedback sources; the daemon pulls sources on a schedule. omp and the kind sude are gone.
- success_signal: On a workspace seeded from a copy of `~/quaqua`, one real task runs end to end on the new binary: brief, fanout to at least 2 different harnesses, cross-harness review bound to a candidate sha, gate, merge into the task's project integration branch, with every kind, harness, model and effort read from SQLite. In the same run: (a) one harness is added with `quaqua config set` only (no rebuild) and `config export` round-trips to an equivalent config; (b) at least 2 dependent tasks run in DAG order, one off-topology spawn and one Peer-to-Peer mail are refused by the daemon and journaled, and a worker answers a query from the code KG; (c) a Supervisor job scores that run's worker conversations and files at least one rule/skill proposal in the backlog as high risk awaiting anh iu; (d) a non-claude worker's `git push` or out-of-band spawn is blocked (native hook or daemon) with evidence; (e) a farm test/gate failure becomes a bug proposal in the backlog, the CoS approves it as low risk with a recorded verdict, and it becomes a task; (f) an entry in anh iu's idea inbox becomes a feature proposal in the backlog; (g) the CLI prints events, transcript, tool calls, tokens/cost (or `unknown`) and candidate sha for every worker of the run; (h) with the project's `WORKSPACE_PROTOCOL.md` setting a worker cap of N, spawn N+1 is refused. (anh iu 2026-11-13: grill, then refine)
- actors: anh iu (owner: sets config, decides high-risk proposals, approves main merges); the CoS (chief: intake, low-risk approvals, integration); the Supervisor (scheduled jobs plus an on-demand agent); at most one Lead per project; Peers on every harness; herdr 0.9.5 (panes, agent kinds, readiness).
