# Harness, Loop and Graph: the enhanced edition of agent engineering with a Chief of Staff

## Goal
- outcome: quaqua is rebuilt as a new crate `qq-core` (bin `qq`) beside the old one in ~/Lab/quaqua; it lands on `main` phase by phase and replaces the old crate as soon as it runs one real task end to end, and the rest of the factory is then built on the new binary, so that it works as a basic software factory run by a Chief of Staff. A behaviour of the old binary that was not carried over is found by use and filed as feedback. A long-running farm daemon is the hub: the CoS or a Lead on herdr fans out workers across any harness herdr knows by agent kind (claude, pi and agy through native drivers; opencode, codex later and others through the generic driver) chosen per kind; the daemon owns dispatch, liveness, one home for state, event-driven journaling, the fence, the task DAG, schedules and triggers, and the CLI is its client. Roles are anh iu, the CoS (chief: intake, project-level integration), the Supervisor (governance: observes, scores, asks Leads, proposes; no orders, no acceptance), at most one Lead per project (sole arbiter inside its project) and Peers (one bounded outcome each, spawned by that Lead or, for a project without a Lead, by the CoS; implementation tools only, no orchestration, no peer mail). Harness, model, effort, roster and role topology are data in a SQLite config: `quaqua init` seeds it from toml, edits go through `quaqua config set`, `quaqua config export` dumps toml, engine default changes surface via `config diff`. Per-project tactics live in a `WORKSPACE_PROTOCOL.md` in each repo, read by the daemon and the Lead. A new harness that herdr knows by agent kind runs through a generic driver with no rebuild. The workspace documents (AGENTS.md, rules, models.md, playbooks) describe the new commands and roles at the switch. Graph = task DAG + role topology graph (spawn/mail/report edges). KB = zbrain plus read-only code lookup through language servers on demand, read-only for workers, over a fixed entity schema in SQLite. Every run is recorded (events, transcript, tool calls, tokens/cost, artifacts, candidate sha) and read through the CLI. Inner loop = workers running the skill set of their role, injected per driver. Outer loop = three proactive loops feeding one risk-split backlog: bug fixes from failure signals, self-improvement from scored conversations, product work from feedback sources; the daemon pulls sources on a schedule. omp is gone; the kind sude stays, on claude.
- success_signal: Switch signal: on an isolated herdr session seeded from a copy of `~/quaqua`, one real task runs end to end on the new binary: brief, fanout to at least 2 different harnesses, cross-harness review bound to a candidate sha, gate, merge into the task's project integration branch, with every kind, harness, model and effort read from SQLite. When it passes, the live farm moves to the new binary and `crates/quaqua` is deleted. Factory signal, on the new binary, each clause proven when its phase lands: (a) one harness is added with `quaqua config set` only (no rebuild) and `config export` round-trips to an equivalent config; (b) at least 2 dependent tasks run in DAG order, one off-topology spawn and one Peer-to-Peer mail are refused by the daemon and journaled, and a worker answers a symbol query through the read-only code lookup; (c) a Supervisor job scores a run's worker conversations and files at least one rule/skill proposal in the backlog as high risk awaiting anh iu; (d) a non-claude worker's `git push` or out-of-band spawn is blocked (native hook or daemon) with evidence; (e) a farm test/gate failure becomes a bug proposal in the backlog, the CoS approves it as low risk with a recorded verdict, and it becomes a task; (f) an idea file in anh iu's idea inbox (`inbox/ideas/` in the workspace, one markdown file per idea) becomes a feature proposal in the backlog; (g) the CLI prints events, transcript, tool calls, tokens/cost (or `unknown`) and candidate sha for every worker of a run; (h) with the project's `WORKSPACE_PROTOCOL.md` setting a worker cap of N, spawn N+1 is refused. (anh iu 2026-11-13: grill, then refine; 2026-11-15: MVP review)
- actors: anh iu (owner: sets config, decides high-risk proposals, approves main merges); the CoS (chief: intake, low-risk approvals, integration); the Supervisor (scheduled jobs plus an on-demand agent); at most one Lead per project; Peers on every harness; herdr 0.9.5 (panes, agent kinds, readiness).
