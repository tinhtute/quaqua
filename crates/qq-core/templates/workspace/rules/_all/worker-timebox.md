# Worker time budget & watchdog

- The brief's `Time budget: <N> min` line **is** the budget: `quaqua worker prompt` reads it (`PROMPT_WORKER_BUDGET_SEC` overrides when set; neither → 2700s). Check a brief before spawning: `quaqua worker prompt --check-brief "<brief>"` validates its headers and prints `budget=<sec>s source=brief|env|default` (exit 1 on a bad brief). The budget is persisted in `runs/.<name>.budget`.
- The brief's `Cost budget: $<x>` line is the money twin. After `quaqua worker cleanup` the CoS reads the worker's real spend via `quaqua status --metrics` and writes `cost=$<y>/$<x>` on the `runs/<name>.md` cleanup line in `memory/YYYY-MM-DD.md`. Over budget with nothing landed → say so in the same line; it is evidence, not a kill switch.
- `quaqua worker prompt` watches the worker while it waits for `runs/<name>.md`. Exit codes: `0` run file printed · `1` usage error (bad arguments, `--extend` not a positive integer) or `--check-brief` rejecting a brief · `2` hard cap (7200 s) · `3` stall — no pane/worktree change for 600 s, agent idle/done for 120 s, or agent gone · `4` time budget exceeded · `5` blocked on a question/permission · `6` malformed report (missing `## Lessons` / `Verdict:` tail) · `7` provider error that needs a human, raised only when a stalled (`3`) or blocked (`5`) turn ended with no report and the pane reads as a provider error (never from the worker's own output): non-retryable (signed out, quota, billing) at once, or a transient one (overloaded, rate limit, 5xx, network) still failing after `PROMPT_WORKER_RETRY_MAX` (4) resumes spaced `PROMPT_WORKER_RETRY_BASE_MS` ×1,2,4,8 (1 min base); each attempt is journaled as `provider_retry`, the end as `provider_escalate` — each prints a WATCHDOG line on stderr · `8` the core died without an exit record (killed, OOM, panic): read the pane, then `quaqua worker prompt --resume <name>` starts a new wait. After any of 3–8: read the pane, act, then `quaqua worker prompt --resume <name>` to keep waiting (add `--extend <sec>` to grant a worker that is still progressing more time; the cap stays absolute). The brief's `Time budget: <N> min` sets the budget.
- At the budget deadline, if the last observed change (pane fingerprint or worktree diff) is within 2 polls, the script grants **one** grace of 25% of the budget — clamped by the cap, once per task (`runs/.<name>.grace`), printed as `WATCHDOG grace +<sec>s (progressing)`. Past the deadline with a **changed worktree diff**, it also keeps granting bounded extensions of 25% of the budget up to +50% total (`runs/.<name>.autoext`, printed `WATCHDOG auto-extend +<sec>s (diff progressing, cap <cap>s, …)`); pane churn alone does not extend. Exit 4 only when nothing moved; a static pane exits 4 at the deadline.
- Budget too small for a worker that is still making progress → `quaqua worker prompt --resume <name> --extend <sec>` adds `<sec>` to that name's persisted allowance and keeps waiting (prints `WATCHDOG extend +<sec>s`). Manual path; beyond it only the automatic diff-progress extensions above apply. Plain `--resume` keeps the old, already-spent allowance. The cap is absolute — `--extend` past it still exits 2.
- At 80% of the budget the script sends **one** soft nudge (never again, never kills, not re-sent after an extend): wrap up, commit, write `runs/<name>.md` with a `## Blockers` section for what is left. When you see that nudge, do exactly that.
- On exit 3, 4, 5, 7 and 8 `quaqua worker prompt` prints the pane's last 40 lines on stderr under one `WATCHDOG pane tail <name>` header (a failed read prints one line saying why; on `pane read failed: agent_not_idle` run `herdr agent read <NAME> --source visible`), so the CoS reads that, acts on it, then `quaqua worker prompt --resume <name>` continues the wait. It never blind re-prompts. `blocked` can be stale — read the pane first; if it is working, just wait again.
- Long waits with no output are fine — the stall clock only measures *observable progress* (pane content or worktree diff). Keep working and it stays quiet.
- Pilots and spikes (testing an unproven tool or approach) use `Playbook: prototype`, and `--check-brief` rejects one whose Time budget exceeds `timers.pilot_budget` (config db, seeded from team.toml). At that budget with no PASS, stop: write `## Blockers` with evidence, then CoS asks the advisor once and decides keep / drop / one more timeboxed try (≤15 min). Never stack fixes on a failing pilot past the budget — 2026-10-08, srt pilot (3 stacked blockers, >30 min).
- Builders run only the targeted tests named in the brief (`cargo test --locked -p qq-core <filter>`), in the foreground. Never wait with a `pgrep -f` loop: it matches the caller's own command line — 2026-10-17, runs/quaqua-intake-lead.md
